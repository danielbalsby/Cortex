## Required handoff fields

Every Product-to-Architecture handoff must contain:

1. Product artifact ID and version.
2. User problem, clinical context and desired outcome.
3. Actors and explicit human decision authority.
4. Proposed capability relation and whether it changes an existing contract.
5. Scope and non-scope.
6. Information types, sources, provenance and ownership hypotheses.
7. Normal, unknown, conflict, degraded and failure outcomes.
8. Observable Product acceptance criteria and intended verification relation.
9. Attention, accessibility, equity, privacy, security and organizational-impact considerations.
10. Upstream rationale, open issues, assumptions and requested Architecture decision.

Unknown fields remain `TODO`; they are not guessed.

## Lifecycle

An interface record moves from `OPEN` to `UNDER REVIEW` only when a named Architecture reviewer accepts the handoff for review. It becomes `RESOLVED` only through a referenced accepted Architecture decision or approved architecture artifact. Product closure alone cannot resolve an Architecture-owned boundary.

If a resolved interface is later replaced, it is marked `SUPERSEDED` with bidirectional links; rows are not deleted.
